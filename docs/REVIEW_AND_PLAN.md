# 开发方案审阅与实施计划

审阅日期：2026-10-31（Asia/Shanghai）。原始方案保持不变。

## Android 用户确认约束（2026-10-31）

Android 前端采用 Kotlin + Jetpack Compose 原生架构，禁止 WebView、H5 嵌入和网页套壳。
客户端通过结构化 API 获取数据，按 Compose UI、ViewModel / StateFlow、Repository、API 数据层逐步拆分。
手续费变更弹窗与后台提醒须分别实现 Android 原生 Dialog 和系统通知，单独验收。
现有 Web 监控页不作为 Android App 的界面实现；Android 目前仅有原生最小源码，完整页面、分层、通知和 APK 验收仍待完成。

## 审阅结论

单机 asyncio + SQLite WAL、独立持仓保护、仅模拟交易的方向合理。分阶段实现，先证明数据可用，再启用信号。

需要补齐的具体条件：

1. 行情连通与可交易资格分开验收。exchangeInfo需要API Key；V0.2已取得用户Key并核验股票池，但仍未验证实盘交易权限或费用。
2. 盘口数量不能作为成交量。当前 K 线无样本；需延长采样，验证累计量、周期边界、更新时间及缺失补齐，证据不足一律 WATCH_ONLY。
3. ORB 完整性必须检查所有预期区间与断线缺口；盘中基准仅用已完成历史 K 线。
4. 历史相同时段成交量样本尚无来源，不能靠瞬时报价解除 COLD_START。
5. 价格、资金、数量及费用统一 Decimal；金额预算、费用、最小名义额和价格精度缺失时禁止开仓。
6. 日历须含休市及提前收盘；不能只用周一至周五判断。日切按纽约交易日，运行时间用单调时钟。
7. SQLite 写入队列溢出须暂停开仓并告警；订单幂等、资金预占、重启恢复必须先于自动模拟交易。
8. 模拟撮合不得重复消费同一盘口流动性；部分成交和未知撤单状态须阻止重复敞口。
9. 股票CSV和Key已提供。发行人地区/市值证据、费用和模拟预算仍未齐备，按数据不足记录，不生成替代事实。
10. 服务器Python3.14.4、开发机3.11已分别通过61项测试；继续维护依赖版本和跨版本验证。
