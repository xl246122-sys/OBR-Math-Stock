# V0.4.1 模式控制开发进度（未发布）

2026-10-31。本次用户要求增加实盘/模拟盘互斥开关。**目前仅完成模式控制、模拟盘开关和实盘请求格式离线校验；实盘交易功能未完成，不能使用真实资金下单。** 生产仍运行已发布的 V0.4.0，本次未更改服务器、未安装交易 Secret、未调用任何真实下单或撤单接口。

## 已实现与验证

- 原生 Android 设置页两个开关；模拟盘控制 PAPER/OFF，实盘开关明确显示未就绪并禁用。监控旧版本服务器时禁用模式操作，不假装切换成功。
- 模式互斥、SQLite 原子保存及审计记录、revision 乐观并发检查；实时 worker 与模式切换共享锁，切换前的模拟循环先完成，切换后不再接受旧信号。
- 关闭模拟开仓后，下轮独立风控循环取消未成交买单、释放预占资金，并继续已有模拟持仓退出保护。关闭开关不是强制清仓。
- 新增 GET/POST `/api/v1/trading-mode`；POST 同时需要监控 Bearer 和独立 `X-OBR-Control-Token`。服务器 `OBR_CONTROL_TOKEN` 至少 32 字符，必须不同于监控令牌；未配置返回 503。本次未创建或发布该令牌。
- Nginx 本地模板仅为上述精确路径允许 POST，其余监控路径仍只读；生产 Nginx 尚未修改。
- 实盘选择始终返回 409 `LIVE_EXECUTION_NOT_CONNECTED`，不会把模拟订单标成实盘。即使磁盘遗留 LIVE 状态，重启也切 OFF，需重新核验。
- `app/live_contract.py` 仅构造/验证官方 LIMIT/RTH/DAY 请求参数，不含 HTTP 传输、签名或真实执行；要求显式钱包/结算资产、合规 clientOrderId，关闭股票代币化。
- Python 124 项测试通过；Android assembleDebug、5 项 JVM 测试和 lintDebug 通过。尚未真机验收。
- 预览 APK：`artifacts/OBR-Math-0.4.1-mode-preview-debug.apk`，versionCode 6。连接当前生产 V0.4 时开关不可操作，必须先发布对应后端。

## 实盘仍待完成

1. 已确认资金规则：MAIN 现货钱包的 USDC 买入，卖出结算到 CARD，用户明确接受；不自动划转。仅美国上市的正规股票与 ETF，禁止股票代币化、其他市场或类型不明产品。
2. 对接真实账户余额、已有持仓、未完成订单及成交对账，确认账户美股权限和适用费率；建立实盘独立账本和风险限额。
3. 签名请求传输、真实订单生命周期、部分成交、撤单确认、超时结果未知与重启对账；禁止用模拟盘口成交结果代替交易所成交。
4. 用户订单回报订阅与断线恢复、限速、故障测试、实盘进入条件及退出后未完成订单处理。
5. 完整执行链路验收后才可讨论由用户本人启用实盘；不能把当前禁用开关当作已交付的实盘功能。

## 用户范围已落实（2026-10-31）

`app/live_scope.py` 保存 MAIN/USDC、卖出 CARD、禁止自动划转及仅 STOCK/ETF 的约束。`limit_request` 现在拒绝非 MAIN 资金来源、非 USDC 结算资产及缺少有效资产证据的标的；元数据须匹配代码、美国上市、非代币化股票/ETF，具备来源引用和最长 24 小时有效期。股票池 CSV 与可交易方向不视为资产类别证据。实际权威元数据加载器仍未接通，不代表现有 479 个代码已核验为可实盘交易。

该模块仍是离线请求校验，不包含真实订单传输。实时账户对账、签名执行、订单生命周期和资产证据接入仍待完成，实盘开关保持禁用，生产 V0.4 未变更。用户已经确认上述结算方式，无需再次询问同一钱包偏好。
